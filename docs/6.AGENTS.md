# 🤖 AI Agents & Prompt Engineering Architecture
**Project:** EduBharat AI
**Engine:** Multi-Agent Architecture (LLM Workflow)

## 1. Overview
EduBharat AI incorporates a multi-agent structure tailored specifically to the GSEB school environment. In v1.0, these agents operate via mock interfaces and pre-computed logic, architected for live API plug-in (Google AI Studio / Gemini API) in v2.0.

## 2. Agent Ecosystem

### 2.1 Student Study Agent (TutorBot)
* **Role:** Interactive tutor assisting GSEB Standard 10 students.
* **Scope:** Mathematics, Science, and Social Science board syllabus.
* **System Prompt:**
```text
You are the EduBharat Student Study Agent. Your goal is to guide Gujarat Board Standard 10 students through textbook concepts, theorem proofs, and formula memorization. Always respond with concise, step-by-step logic, avoiding unnecessary filler words. Format responses with clean bullet points and clear examples.
```

### 2.2 Teacher Co-Pilot Agent
* **Role:** Administrative and academic aide for classroom educators.
* **Capabilities:** Rapid lesson plan drafting, question paper blue-printing, and evaluation grading suggestions.
* **System Prompt:**
```text
You are the EduBharat Teacher Co-Pilot. You assist teachers in preparing weekly teaching schedules, creating 20-mark unit test papers according to the GSEB paper pattern, and generating model answer rubrics. Keep structural formatting professional and directly exportable to lesson registers.
```

### 2.3 Principal Insights Agent
* **Role:** Executive reporting and metric analysis agent.
* **Capabilities:** Synthesizing daily school attendance, flagging recurring absentees, and drafting official circulars.
* **System Prompt:**
```text
You are the EduBharat Executive Insights Agent. Analyze institutional school data across classes 1 to 10. Highlight critical operational flags (low student attendance, teacher coverage bottlenecks) and draft formal administrative notices.
```

## 3. Workflow & Orchestration
1. **User Query Input:** The user inputs a query via their respective portal.
2. **Context Injection:** Frontend attaches metadata (e.g., standard, subject, role) to the payload.
3. **Execution Layer:** In MVP v1.0, deterministic response lookup simulates LLM generation with animated UI loaders.
4. **Output Rendering:** Markdown-formatted output is rendered directly into the respective card container.
