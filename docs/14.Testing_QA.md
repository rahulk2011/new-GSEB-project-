# 🧪 Testing & Quality Assurance Protocol
**Project:** EduBharat AI
**Focus:** Mobile-First Responsive Stability & Cross-Browser Verification

## 1. QA Strategy
Because EduBharat AI is engineered as a zero-dependency Single-Page Application (SPA) aimed at low-spec devices, testing prioritizes rendering performance, UI responsiveness, and state stability on mobile viewports.

## 2. Testing Checklist

### 2.1 Viewport & Responsive Design
* **Target Breakpoints:** 360px (compact Android), 412px (modern Android), 768px (tablet).
* **Checks:**
  - Zero horizontal page overflow or unintended layout shifting.
  - Form input elements maintain a minimum 44px tap target size.
  - Text contrast complies with WCAG AA standard against dark backgrounds.

### 2.2 Role-Based State Routing
* **Verification Steps:**
  1. Open Gateway screen and select each role sequentially (Student, Teacher, Principal, Parent).
  2. Verify that non-active portal containers are set to `display: none`.
  3. Ensure active portal renders data correctly without console exceptions.
  4. Test "Back to Gateway" or "Logout" button to verify state flushes cleanly.

### 2.3 Simulated Latency & User Feedback
* **Action:** Trigger the "AI Doubt Solver" or "Broadcast Notice" button.
* **Expected Result:** Loading indicator displays for 1.2s - 1.5s, disables duplicate submission clicks, and renders mock response cleanly.
