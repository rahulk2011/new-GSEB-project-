# 🏗️ Technical System Architecture
**Type:** Monolithic Single-Page Application (SPA)
**Stack:** Vanilla HTML5, CSS3, JavaScript (Zero Dependencies)

## 1. High-Level Overview
To ensure instant load times and bypass complex local server environments during the prototyping phase, EduBharat AI v1.0 is engineered as a single `index.html` file. It relies entirely on client-side rendering and DOM manipulation.

## 2. State Routing (Vanilla JS)
We simulate a Multi-Tenant application using CSS `display` toggling.
* **Views:** 5 isolated `<section>` containers (`#gateway`, `#student`, `#teacher`, `#principal`, `#parent`).
* **Logic:** The `switchView(roleId)` function sets all sections to `display: none` and the target section to `display: flex`.

## 3. Data Layer (Mock JSON)
Instead of an external database, data resides within the `<script>` tag as a JavaScript Object (Mock JSON).
* Example: `const mockDb = { student: { progress: 82, board: "GSEB" } };`
* Upon routing, JS functions inject this data into the DOM using `.innerHTML`.

## 4. Performance & Offline Capability
* **Zero CDNs:** By not using external libraries (like React, Tailwind, or Bootstrap CDNs), the app is entirely self-contained.
* Once loaded, it can function fully offline during school demonstrations.

## 5. AI API Simulation
To demonstrate "AI generation" (like the AI Doubt Solver), we use `setTimeout()` to introduce a 1.5-second artificial latency, showing a CSS loading spinner before displaying a pre-written mock response.
